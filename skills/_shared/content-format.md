# Content source format

Every skill writes files in this format. `packages/content-schema` turns this document into JSON Schemas (Phase 0, epic F-6), and CI validates `content/` against them. If this document and the schema disagree, the schema wins and this document gets fixed.

The examples below show **shape only**. Their text is placeholder, not study content.

---

## 1. Layout of `content/`

```
content/
├─ exams/{exam_id}.json                         exam + its profiles (cycles)
├─ blueprints/{exam_profile_id}/{paper}.v{n}.json   exam pattern (exam-blueprint)
├─ graph/{subject_id}/subject.json              subject, units, chapter list
├─ graph/{subject_id}/{chapter_slug}.json       chapter → topics → subtopics → concepts
├─ exam-maps/{exam_profile_id}.json             concept depth, weightage, priority per exam
├─ lessons/{subject_id}/{chapter_slug}/{topic_slug}.{mode}.json   deep_dive | quick_revision
├─ questions/{subject_id}/{chapter_slug}/{topic_slug}.json
├─ pyq/{exam_id}/{paper_id}.json                one previous-year paper
├─ mnemonics/{subject_id}/{chapter_slug}.json
├─ extras/{subject_id}/{chapter_slug}/…         cheat sheets, storybooks, experiments, role plays
├─ media/requests/{subject_id}/{chapter_slug}.json   media needed by the files above
└─ coverage/{exam_profile_id}.json              generated by syllabus-mapper and content-qa; never hand-edited
```

Large binaries never go in git. Media goes to R2 staging, and `content/` only holds references.

## 2. IDs

- Lowercase, ASCII, dot-separated, hyphens inside a part. They never change once published. If a concept is split, the old ID is kept as an alias.
- Hierarchy: `subject` → `subject.chapter` → `subject.chapter.topic` → `subject.chapter.topic.subtopic` → `subject.chapter.topic.subtopic.concept`.
  - Example shape: `phy.kinematics.relative-motion.one-dimension.relative-velocity`.
- Cards: `{topic_id}:{mode}:{nn}` (for example `…relative-motion:dd:07`). Questions: `q.{topic_id}.{nnnn}`. Mnemonics: `m.{concept_id}.{n}`. Media requests: `img.{chapter}.{slug}`, `anim.{…}`, `sim.{…}`, `m3d.{…}`, `pano.{…}`, `audio.{…}`.
- Subject IDs map to a colour family through `subjectMap` in `packages/tokens/tokens.json`. A new subject needs an entry there.

## 3. Common fields

**Localised text** is an object keyed by locale. Phase 1 requires both `en` and `hi`:

```json
{ "en": "…", "hi": "…" }
```

- Hindi is standard Devanagari Hindi, written the way NCERT Hindi-medium books write it. On first use in a lesson, a technical term is followed by its English term in brackets.
- Maths and chemistry use LaTeX inside `$…$` (inline) or `$$…$$` (display). The build renders them to SVG. Never write formulas as plain text.

**Every file** carries:

```json
{
  "schema": "lesson@1",
  "status": "draft",
  "sources": [
    { "kind": "ncert", "ref": "Class 11 Physics Part 1, Ch 4, §4.3", "url": "https://ncert.nic.in/…" }
  ],
  "authored_by": "skill:lesson-author",
  "reviewed_by": null,
  "updated": "2026-10-28"
}
```

- `status`: `draft` → `review` → `published` (set by the publish job only) → `retired`.
- `sources[].kind`: `ncert`, `official` (an exam notification or syllabus), `openstax`, `pyq`, `textbook`, `paper`, `dataset`, `other`. Facts need a source a reviewer can open.

```json
{

  "name": { "en": "JEE Main", "hi": "जेईई मेन" },
  "category": "engineering",
  "conducting_body": "NTA",
  "official_url": "https://…",
  "profiles": [
    { "id": "jee-main-2027", "cycle": "2027", "locales": ["en", "hi"], "papers": ["paper-1"] }
  ]
}
```

## 5. Graph (`graph/{subject_id}/{chapter_slug}.json`)

```json
{
  "schema": "chapter@1",
  "id": "phy.kinematics",
  "subject": "phy",
  "unit": "phy.mechanics",
  "name": { "en": "…", "hi": "…" },
  "ncert_ref": "Class 11 Physics Ch 4",
  "topics": [
    {
      "id": "phy.kinematics.relative-motion",
      "name": { "en": "…", "hi": "…" },
      "subtopics": [
        {
          "id": "phy.kinematics.relative-motion.one-dimension",
          "name": { "en": "…", "hi": "…" },
          "concepts": [
            {
              "id": "phy.kinematics.relative-motion.one-dimension.relative-velocity",
              "name": { "en": "…", "hi": "…" },
              "kind": "formula",
              "intrinsic_depth": 2,
              "summary": { "en": "…", "hi": "…" },
              "key_points": [ { "en": "…", "hi": "…" } ],
              "prerequisites": ["phy.kinematics.motion-1d.velocity"],
              "related": [],
              "syllabus_refs": ["jee-main-2027:physics:unit-2:item-3"]
            }
          ]
        }
      ]
    }
  ]
}
```

- `kind`: `fact`, `definition`, `formula`, `derivation`, `process`, `skill`, `date`, `list`, `diagram`.
- `intrinsic_depth`: L1 basic school, L2 board, L3 competitive basics, L4 advanced, L5 elite (PRD §4.2).
- `key_points` are what a complete explanation must contain. The Feynman tutor grades against them, so make each one specific and checkable.
- `syllabus_refs` point back to lines in the official syllabus. This is how coverage is proved.

## 6. Exam map (`exam-maps/{exam_profile_id}.json`)

```json
{
  "schema": "exam-map@1",
  "exam_profile": "jee-main-2027",
  "concepts": [
    { "id": "phy.kinematics.relative-motion.one-dimension.relative-velocity",
      "depth": 3, "priority": "core", "weightage": null, "pyq_count": null }
  ]
}
```

`weightage` and `pyq_count` stay `null` until `pyq-ingest` computes them from real papers. Never estimate them.

## 7. Lessons (`lessons/…/{topic_slug}.{mode}.json`)

```json
{
  "schema": "lesson@1",
  "id": "phy.kinematics.relative-motion:deep_dive",
  "topic": "phy.kinematics.relative-motion",
  "mode": "deep_dive",
  "estimated_minutes": 14,
  "min_depth": 1,
  "max_depth": 4,
  "concepts": ["…relative-velocity", "…"],
  "cards": [ { "id": "…:dd:01", "type": "story", "concepts": ["…"], "depth": 1, "…": "…" } ]
}
```

Each card has `id`, `type`, `concepts` (at least one), and `depth` (1–5). The app hides cards deeper than the student's exam allows, so one lesson serves several exams. Card types and their extra fields:

| `type` | Fields |
|---|---|
| `story` | `title`, `body`, `media` (image or comic panels), `narration` (audio request, optional) |
| `explainer` | `title`, `body`, `highlights[]` (term + definition), `media`, `narration` |
| `animation` | `title`, `media` (Rive or Lottie request), `caption`, `transcript` |
| `interactive` | `widget` (`drag_sort`, `slider`, `graph`, `tap_reveal`, `label_diagram`, `order_steps`), `config`, `prompt`, `feedback` |
| `sim` | `sim` (sim request ID), `params`, `tasks[]` (prompt, expected measurement, tolerance), `debrief` |
| `model3d` | `model` (3D request ID), `labels[]` (anchor, text), `exploded_view`, `prompt` |
| `pano360` | `pano` (360° request ID), `hotspots[]` (yaw, pitch, title, body), `prompt` |
| `derivation` | `title`, `steps[]` (`latex`, `say`, `why`) |
| `worked_example` | `problem`, `hints[]`, `solution_steps[]`, `answer`, `shortcut` (optional), `common_trap` (optional) |
| `question` | `question` (a question ID from `questions/`) |
| `memory_hook` | `mnemonic` (a mnemonic ID), `media` (optional) |
| `roleplay` | `character` (name, era, portrait request), `persona_prompt`, `goals[]`, `guardrails[]`, `opening_line`, `suggested_replies[]` |
| `video` | `youtube_id`, `start_s`, `end_s`, `concept_timestamps[]` |
| `experiment` | `title`, `materials[]`, `steps[]`, `safety[]`, `why_it_works`, `media` |
| `summary` | `points[]`, `media` (optional) |
| `cheat_sheet_ref` | `sheet` (an extras ID), used in quick revision |

All text fields are localised. `media`, `narration`, `sim`, `model` and `pano` are **request IDs** from `media/requests/` (§11), never URLs.

## 8. Questions (`questions/…/{topic_slug}.json`)

```json
{
  "schema": "questions@1",
  "topic": "phy.kinematics.relative-motion",
  "questions": [
    {
      "id": "q.phy.kinematics.relative-motion.0001",
      "type": "mcq_single",
      "concepts": [ { "id": "…relative-velocity", "weight": 1 } ],
      "depth": 3,
      "exam_styles": ["jee-main", "neet-ug"],
      "stem": { "en": "…", "hi": "…" },
      "options": [ { "id": "a", "text": { "en": "…", "hi": "…" } } ],
      "answer": { "option_ids": ["c"] },
      "solution": {
        "feynman": { "en": "…", "hi": "…" },
        "steps": [ { "en": "…", "hi": "…" } ],
        "shortcut": null,
        "common_traps": [ { "option_id": "b", "why": { "en": "…", "hi": "…" } } ]
      },
      "ideal_time_s": 90,
      "difficulty_estimate": "medium",
      "media": null,
      "use": ["practice", "mock"]
    }
  ]
}
```

- `type`: `mcq_single`, `mcq_multi`, `numerical` (`answer.value` + `answer.tolerance`), `integer`, `matrix_match`, `match_list`, `assertion_reason`, `statement_based`, `paragraph` (a shared passage with child questions), `fill_blank`, `order_steps`.
- `answer` is the server-side key. For `use` containing `mock`, the publish job moves it to `content.question_keys`, so it never ships to devices.
- Every solution has a **Feynman-style** plain-language explanation first, then the formal steps.
- `difficulty_estimate` is the author's guess (`easy`, `medium`, `hard`). Real difficulty comes later from student data. Never claim a question "appeared in N exams" unless `pyq-ingest` linked it.

## 9. PYQ papers (`pyq/{exam_id}/{paper_id}.json`)

```json
{
  "schema": "pyq-paper@1",
  "id": "jee-main-2025-jan-22-s1",
  "exam": "jee-main",
  "year": 2025,
  "session_label": "22 Jan, Shift 1",
  "source": { "kind": "official", "url": "https://…", "retrieved": "2026-10-28" },
  "rights_note": "…",
  "items": [ { "number": 1, "question": "q.phy.….0101", "section": "physics-a", "official_answer": "…", "answer_challenged": false } ]
}
```

The questions themselves go in `questions/` with `"source": "pyq"` in their metadata and a back-link to the paper.

## 10. Mnemonics (`mnemonics/{subject_id}/{chapter_slug}.json`)

```json
{
  "schema": "mnemonics@1",
  "items": [
    {
      "id": "m.chem.periodic-table.groups.group-1.1",
      "concept": "chem.periodic-table.groups.group-1",
      "technique": "acrostic",
      "origin": "traditional",
      "locale": "hi",
      "text": "…",
      "decodes_to": ["…", "…"],
      "exam_style": null,
      "media": "img.periodic-table.group-1-hook",
      "audio": "audio.periodic-table.group-1-rhyme",
      "notes": "…"
    }
  ]
}
```

- `technique`: `acronym`, `acrostic`, `story`, `rhyme`, `song`, `keyword`, `pao`, `major_system`, `peg`, `palace`, `chunking`, `visual`.
- `origin`: `traditional` (widely known; cite where it's commonly taught), `system` (made by the skill).
- `decodes_to` must exactly match the facts it encodes, in order. `content-qa` checks this.

## 11. Media requests (`media/requests/…`)

Content files never contain URLs. They point to a request, and the media skills fulfil it:

```json
{
  "schema": "media-requests@1",
  "requests": [
    {
      "id": "img.kinematics.river-boat",
      "kind": "image",
      "preset": "sunny-scene",
      "subject_family": "physics",
      "brief": "A boat crossing a river, the current shown as gentle arrows, two riverbank trees, no labels",
      "must_show": ["boat heading", "river current direction"],
      "must_not_show": ["text", "numbers"],
      "label_anchors": [ { "id": "current", "x": 0.7, "y": 0.6 } ],
      "alt": { "en": "…", "hi": "…" },
      "used_by": ["phy.kinematics.relative-motion:dd:03"],
      "status": "requested",
      "result": null
    }
  ]
}
```

- `kind`: `image`, `diagram`, `comic`, `pano360`, `animation_rive`, `animation_lottie`, `model3d`, `sim`, `audio_tts`, `audio_song`.
- `status`: `requested` → `generated` → `approved` (or `rejected` with a reason). `result` holds `{ "sha256": "…", "asset_id": "…", "reused": true|false }`.
- Labels are overlaid by the app at `label_anchors`, in the student's language. Images never contain text.

## 12. Blueprints

See `skills/exam-blueprint/SKILL.md`. Blueprints are versioned and never edited in place: a pattern change is a new `v{n}` file.

## 13. Extras (`extras/…`)

`cheat_sheet@1`, `revision_sheet@1`, `storybook@1`, `experiment@1`, `roleplay@1` and `mind_map_template@1` follow the same rules: localised fields, concept links, sources, and media by request ID. `lesson-author` defines their exact fields in its references.
