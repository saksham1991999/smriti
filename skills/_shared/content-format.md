# Content source format

Every skill writes files in this format. The JSON Schemas in `packages/content-schema/schemas/` encode it, and CI runs `pnpm --filter @smriti/content-schema content:check` on `content/`. If this document and a schema disagree, the schema wins and this document gets fixed.

The examples below show **shape only**. Their text is placeholder, not study content. `content/fixtures/` holds a complete fixture course that uses every file type, card type and question type; read it when a shape here is unclear.

---

## 1. Layout of `content/`

```
content/
├─ exams/{exam_id}.json                         exam + its profiles (cycles)
├─ blueprints/{exam_profile_id}/{paper}.v{n}.json   exam pattern (exam-blueprint)
├─ graph/{subject_id}/subject.json              subject, units, chapter order
├─ graph/{subject_id}/{chapter_slug}.json       chapter → topics → subtopics → concepts
├─ exam-maps/{exam_profile_id}.json             concept depth, priority, weightage per exam
├─ lessons/{subject_id}/{chapter_slug}/{topic_slug}.{mode}.json   deep_dive | quick_revision
├─ questions/{subject_id}/{chapter_slug}/{topic_slug}.json
├─ pyq/{exam_id}/{paper_id}.json                one previous-year paper
├─ mnemonics/{subject_id}/{chapter_slug}.json
├─ extras/{subject_id}/{chapter_slug}/…         cheat sheets, revision sheets, storybooks, songs, play activities, experiments, role plays, mind maps
├─ media/requests/{subject_id}/{chapter_slug}.json   media needed by the files above
├─ seed-packs/{variant_id}.json                 what the app ships offline for a store variant
├─ releases.json                                the release gate: what each exam profile ships to production (§6.1)
├─ coverage/syllabus/{exam_profile_id}.json     official syllabus lines (syllabus-mapper)
├─ coverage/inventory/{subject_id}/{chapter_slug}.json   textbook inventory (syllabus-mapper)
└─ coverage/{exam_profile_id}.json              coverage report, generated by content:check --write-coverage; never hand-edited
```

Simulations live outside `content/`, in `sims/{sim_id}/` with a `sim.json` manifest (§14).

Large binaries never go in git. Media goes to R2 staging, and `content/` only holds references.

## 2. IDs

- Lowercase, ASCII, dot-separated, hyphens inside a part. They never change once published. If a concept is split, the old ID is kept in the new concept's `aliases`.
- Hierarchy: `subject` → `subject.chapter` → `subject.chapter.topic` → `subject.chapter.topic.subtopic` → `subject.chapter.topic.subtopic.concept`. Each ID must start with its parent's ID.
  - Example shape: `phy.kinematics.relative-motion.one-dimension.relative-velocity`.
- Cards: `{topic_id}:{dd|qr}:{nn}` (`dd` in a Deep Dive, `qr` in a Quick Revision), for example `…relative-motion:dd:07`.
- Questions: `q.{topic_id}.{nnnn}`. Mnemonics: `m.{concept_id}.{n}`.
- Media requests: `img.{chapter}.{slug}`, `anim.{…}`, `sim.{…}`, `m3d.{…}`, `pano.{…}`, `audio.{…}`. App art that is not tied to a chapter (pets, plants, empty states) uses `img.ui.{slug}`.
- Extras: `cs.` cheat sheet, `rs.` revision sheet, `sb.` storybook, `sg.` song, `pl.` play activity, `ex.` experiment, `rp.` role play, `mm.` mind-map template, followed by the topic or chapter ID.
- Syllabus lines: `{exam_profile}:{subject}:{unit}:{item}`.
- Subject IDs map to a colour family through `subjectMap` in `packages/tokens/tokens.json`. A new subject needs an entry there.

## 3. Common fields

**Localised text** is an object keyed by locale:

```json
{ "en": "…", "hi": "…" }
```

- Locale keys come from a fixed list: `en`, `hi`, and the scheduled languages of India (`as`, `bn`, `brx`, `doi`, `gu`, `kn`, `ks`, `kok`, `mai`, `ml`, `mni`, `mr`, `ne`, `or`, `pa`, `sa`, `sat`, `sd`, `ta`, `te`, `ur`). A profile's `locales` (§4) says which are required. Phase 1 requires `en` and `hi` everywhere.
- Because locale keys are a closed list, a map keyed by anything else is never localised text. That is why answer keys and matches are written as **arrays of pairs** (§8), not as objects keyed by IDs.
- Hindi is standard Devanagari Hindi, written the way NCERT Hindi-medium books write it. On first use in a lesson, a technical term is followed by its English term in brackets.
- Maths and chemistry use LaTeX inside `$…$` (inline) or `$$…$$` (display). Write `\$` for a literal dollar sign. The build renders maths to SVG. Never write formulas as plain text. Each locale must contain the same maths and the same numbers (`content:check` compares them).
- Lists of accepted answers per locale use `{ "en": ["…", "…"], "hi": ["…"] }`.
- Content that is written separately per language, not translated, uses one ID per locale: a mnemonic reference is `{ "en": "m.….1", "hi": "m.….2" }`, and narration is `{ "en": "audio.….en", "hi": "audio.….hi" }`.

**Every file** carries:

```json
{
  "schema": "lesson@1",
  "status": "draft",
  "sources": [
    { "kind": "ncert", "ref": "Class 11 Physics Part 1, Ch 4, §4.3", "url": "https://ncert.nic.in/…" }
  ],
  "authored_by": "skill:lesson-author",
  "reviewed_by": null,
  "updated": "2026-10-28"
}
```

- `status`: `draft` → `review` → `published` (set by the publish job only) → `retired`.
- `sources[]`: `kind` and `ref` are required; `url`, `retrieved`, `pages` and `licence` are optional. `kind` is one of `ncert`, `official` (an exam notification or syllabus), `openstax`, `pyq`, `textbook`, `paper`, `dataset`, `other`. Facts need a source a reviewer can open.
- `notes` (optional) is free text for reviewers.
- `fixture: true` marks test data. Every file under `content/fixtures/` must carry it, no file elsewhere may, and the publisher refuses to send fixtures anywhere but a local folder.

## 4. Exams and profiles (`exams/{exam_id}.json`)

```json
{
  "schema": "exam@1",
  "id": "jee-main",
  "name": { "en": "JEE Main", "hi": "जेईई मेन" },
  "category": "engineering",
  "conducting_body": "NTA",
  "official_url": "https://…",
  "profiles": [
    {
      "id": "jee-main-2027",
      "cycle": "2027",
      "locales": ["en", "hi"],
      "papers": ["paper-1"],
      "schedule": null
    }
  ]
}
```

- `category`: `engineering`, `medical`, `civil_services`, `ssc`, `banking`, `railways`, `defence`, `state`, `school`.
- Profile IDs start with the exam ID.
- `audience` (optional): `standard` (the default) or `little_learner` for class 1–5 profiles. A little learner profile's coverage needs a teaching item (Deep Dive teaching card, storybook or song) and a play activity per concept, instead of revision cards, practice questions, spaced-repetition cards and formula worked examples.
- `schedule` stays `null` until dates are announced. Then it is a list of `{ "kind", "date", "source_url" }`, where `kind` is `application_open`, `application_close`, `exam_window_start`, `exam_window_end`, `exam_day` or `result`, and `source_url` is the official notification.

## 5. Subjects and graph

**Subject** (`graph/{subject_id}/subject.json`):

```json
{
  "schema": "subject@1",
  "id": "phy",
  "name": { "en": "…", "hi": "…" },
  "color_family": "physics",
  "sort": 1,
  "units": [ { "id": "phy.mechanics", "name": { "en": "…", "hi": "…" } } ],
  "chapters": ["phy.kinematics", "…"]
}
```

`color_family` is one of `physics`, `chemistry`, `biology`, `maths`, `history`, `polity`, `language`. `chapters` is the teaching order; the first chapters are the free and seed-pack chapters.

**Chapter** (`graph/{subject_id}/{chapter_slug}.json`):

```json
{
  "schema": "chapter@1",
  "id": "phy.kinematics",
  "subject": "phy",
  "unit": "phy.mechanics",
  "name": { "en": "…", "hi": "…" },
  "ncert_ref": "Class 11 Physics Ch 4",
  "topics": [
    {
      "id": "phy.kinematics.relative-motion",
      "name": { "en": "…", "hi": "…" },
      "subtopics": [
        {
          "id": "phy.kinematics.relative-motion.one-dimension",
          "name": { "en": "…", "hi": "…" },
          "concepts": [
            {
              "id": "phy.kinematics.relative-motion.one-dimension.relative-velocity",
              "name": { "en": "…", "hi": "…" },
              "kind": "formula",
              "intrinsic_depth": 2,
              "summary": { "en": "…", "hi": "…" },
              "key_points": [ { "en": "…", "hi": "…" } ],
              "prerequisites": ["phy.kinematics.motion-1d.velocity"],
              "related": [],
              "contrasts": [],
              "applies_in": [],
              "aliases": [],
              "syllabus_refs": ["jee-main-2027:physics:unit-2:item-3"]
            }
          ]
        }
      ]
    }
  ]
}
```

- `kind`: `fact`, `definition`, `formula`, `derivation`, `process`, `skill`, `date`, `list`, `diagram`.
- `intrinsic_depth`: L1 basic school, L2 board, L3 competitive basics, L4 advanced, L5 elite (PRD §4.2).
- `key_points` are what a complete explanation must contain. The Feynman tutor grades against them, so make each one specific and checkable.
- `prerequisites` point from this concept to the concepts it needs. They may cross chapters and subjects, must exist, and must not form a cycle.
- `related`, `contrasts` and `applies_in` are optional links. `aliases` keeps old IDs after a split.
- `syllabus_refs` point back to lines in the official syllabus (§15). This is how coverage is proved.

## 6. Exam map (`exam-maps/{exam_profile_id}.json`)

```json
{
  "schema": "exam-map@1",
  "exam_profile": "jee-main-2027",
  "stats_basis": null,
  "concepts": [
    { "id": "phy.kinematics.relative-motion.one-dimension.relative-velocity",
      "depth": 3, "priority": "core", "weightage": null, "pyq_count": null }
  ]
}
```

- `depth` is how deep this exam goes for the concept. Lesson cards deeper than it are hidden for this exam.
- `priority`: `core` by default, `optional` only when the syllabus marks it so, and `high_yield` only when `pyq-ingest` computed it from real papers.
- `weightage` and `pyq_count` stay `null` until `pyq-ingest` computes them. Never estimate them. When they are set, `stats_basis` must name the papers and the date: `{ "papers": ["…"], "computed_at": "2026-10-28", "method": "…" }`.

### 6.1 Release gate (`releases.json`)

```json
{
  "schema": "releases@1",
  "status": "review",
  "authored_by": "owner",
  "updated": "2026-10-31",
  "profiles": {
    "jee-main-2027": { "subjects": ["phy"], "chapters": ["chem.basic-concepts"] }
  }
}
```

- One file at the content root. For each exam profile it lists the whole subjects and the single chapters released to production. A profile that is not listed has nothing released. It starts empty, and only the owner adds to it. Content skills never edit it.
- `content:check` fails when a released subject or chapter is below 100% coverage, has no syllabus, or has a chapter with no inventory (PRD §14). Unreleased gaps are warnings.
- A production publish (`--env production`) builds only released chapters, and every media item in them must be approved. The rest is skipped and listed under `unreleased` in the publish report. Staging and local builds publish everything, and ship media that is not approved yet as unavailable.

## 7. Lessons (`lessons/…/{topic_slug}.{mode}.json`)

```json
{
  "schema": "lesson@1",
  "id": "phy.kinematics.relative-motion:deep_dive",
  "topic": "phy.kinematics.relative-motion",
  "mode": "deep_dive",
  "estimated_minutes": 14,
  "min_depth": 1,
  "max_depth": 4,
  "concepts": ["…relative-velocity", "…"],
  "bites": [
    { "id": "bite-1", "title": { "en": "…", "hi": "…" },
      "subtopic": "phy.kinematics.relative-motion.one-dimension",
      "card_ids": ["…:dd:01", "…:dd:02", "…:dd:03"], "estimated_minutes": 4 }
  ],
  "cards": [ { "id": "…:dd:01", "type": "story", "concepts": ["…"], "depth": 1, "…": "…" } ]
}
```

- `mode` is `deep_dive` or `quick_revision`. The card ID code must match (`dd` or `qr`).
- Each card has `id`, `type`, `concepts` (at least one), `depth` (1–5, within `min_depth`…`max_depth`) and an optional `source`. The app hides cards deeper than the student's exam allows, so one lesson serves several exams.
- `bites` (optional) split a Deep Dive into short sittings. If present, they list every card exactly once, in order. If absent, the app ends a bite after each `summary` card.
- `min_app_version` (optional) holds the lesson back from older apps.
- A Quick Revision is a short pass: a `cheat_sheet_ref`, rapid `question` cards, a `summary` and `common_traps`.

Card types and their extra fields (required unless marked optional):

| `type` | Fields |
|---|---|
| `story` | `title`, `body`, `media` (optional), `panels[]` (optional, comic panels: `media`, `caption`), `narration` (optional, per-locale audio) |
| `explainer` | `title`, `body`, `media`, `highlights[]` (optional: `term`, `definition`), `narration` (optional) |
| `formula` | `title`, `latex`, `symbols[]` (`symbol`, `meaning`, `unit`), `spoken` (optional), `conditions` (optional), `vault_id` (optional), `media` (optional) |
| `animation` | `title`, `media` (an `anim.` request), `poster` (optional), `caption`, `transcript` |
| `interactive` | `prompt`, `widget`, `config` (shape depends on `widget`, below), `feedback` (optional: `correct`, `wrong`), `media` (optional) |
| `sim` | `sim` (a `sim.` request), `title` (optional), `params` (optional), `tasks[]` (`id`, `prompt`, `measurement`, `expected`), `debrief`, `fallback` |
| `model3d` | `model` (an `m3d.` request), `prompt`, `labels[]` (`anchor`, `text`), `exploded_view`, `poster` (optional), `fallback` |
| `pano360` | `pano` (a `pano.` request), `prompt`, `hotspots[]` (`id`, `yaw`, `pitch`, `title`, `body`), `fallback` |
| `derivation` | `title`, `steps[]` (`latex`, `say`, optional `why`) |
| `worked_example` | `problem`, `solution_steps[]`, `answer`, `answer_value` (optional: `value`, `unit`, `tolerance`), `hints[]` (optional), `shortcut` (optional), `common_trap` (optional), `media` (optional) |
| `question` | `question` (a question ID from `questions/`) |
| `memory_hook` | `mnemonic` (one mnemonic ID per locale), `media` (optional) |
| `roleplay` | `character` (`name`, `era`, `portrait`), `persona_prompt`, `goals[]`, `guardrails[]`, `opening_line`, `suggested_replies[]`, `script` (optional `rp.` extra) |
| `video` | `youtube_id`, `start_s`, `end_s`, `title` (optional), `concept_timestamps[]` (optional: `concept`, `t_s`) |
| `experiment` | `title`, `materials[]`, `steps[]`, `safety[]`, `adult_supervision`, `why_it_works`, `media` (optional) |
| `summary` | `points[]`, `media` (optional) |
| `cheat_sheet_ref` | `sheet` (a `cs.` or `rs.` extra), used in Quick Revision |
| `common_traps` | `traps[]` (`mistake`, `correct`), `title` (optional) |

Interactive `config` by `widget`:

| `widget` | `config` |
|---|---|
| `drag_sort` | `items[]` (`id`, `text`), `bins[]` (`id`, `label`), `answer[]` (`{ "item": "…", "bin": "…" }`) |
| `slider` | `min`, `max`, `step`, `unit`, `initial` (optional), `target` (optional: `value`, `tolerance`), `guidance` (optional) |
| `graph` | `x`, `y` (axes: `min`, `max`, `step`, `label`, `unit`), `handle` (`point` or `curve`), `initial` (optional: `x`, `y`), `target` (optional: `x`, `y`, `tolerance`) |
| `tap_reveal` | `tiles[]` (`id`, `label`, `text`, optional `anchor`) |
| `label_diagram` | `media`, `spots[]` (`id`, `anchor`, a label anchor from the image's request), `labels[]` (`id`, `text`), `answer[]` (`{ "spot": "…", "label": "…" }`) |
| `order_steps` | `steps[]` (`id`, `text`), listed in the correct order; the app shuffles them |

- All text fields are localised. `media`, `narration`, `sim`, `model` and `pano` are **request IDs** from `media/requests/` (§12), never URLs.
- `sim`, `model3d` and `pano360` cards need a `fallback` (`body`, optional `media` and `video_ref`) for devices that cannot load them.
- `video` and `roleplay` cards need the network. They never carry the only explanation of a concept.
- A `question` card may only point to a question whose `use` includes `lesson` or `practice`.

## 8. Questions (`questions/…/{topic_slug}.json`)

```json
{
  "schema": "questions@1",
  "topic": "phy.kinematics.relative-motion",
  "questions": [
    {
      "id": "q.phy.kinematics.relative-motion.0001",
      "type": "mcq_single",
      "concepts": [ { "id": "…relative-velocity", "weight": 1 } ],
      "depth": 3,
      "exam_styles": ["jee-main", "neet-ug"],
      "stem": { "en": "…", "hi": "…" },
      "options": [ { "id": "a", "text": { "en": "…", "hi": "…" } } ],
      "answer": { "option_ids": ["c"] },
      "hints": [ { "en": "…", "hi": "…" } ],
      "solution": {
        "feynman": { "en": "…", "hi": "…" },
        "steps": [ { "en": "…", "hi": "…" } ],
        "shortcut": null,
        "shortcut_fails_when": null,
        "common_traps": [ { "option_id": "b", "why": { "en": "…", "hi": "…" } } ]
      },
      "ideal_time_s": 90,
      "difficulty_estimate": "medium",
      "media": null,
      "use": ["practice", "lesson"],
      "source": "original"
    }
  ]
}
```

Question types and their fields:

| `type` | Fields | `answer` |
|---|---|---|
| `mcq_single` | `options[]` (2–6) | `{ "option_ids": ["c"] }` (exactly one) |
| `mcq_multi` | `options[]` | `{ "option_ids": ["a", "c"] }` |
| `assertion_reason` | `assertion`, `reason`, `options[]` | one option |
| `statement_based` | `statements[]`, `options[]` | one option |
| `numerical` | `answer_format` (optional: `allow_scientific`, `decimals`) | `{ "value": 2.5, "unit": "m/s", "tolerance": { "abs": 0.05 } }` (`unit` is `null` when dimensionless; `tolerance` takes `abs` and/or `rel`) |
| `integer` | | `{ "value": 4, "unit": null }` |
| `matrix_match` | `rows[]`, `columns[]` | `{ "pairs": [ { "row": "p", "columns": ["1", "3"] } ] }` |
| `match_list` | `list_i[]`, `list_ii[]`, `options[]` (optional) | one option when `options` are given, else `{ "pairs": [ { "left": "a", "right": "3" } ] }` |
| `fill_blank` | `blanks[]` (`id`, optional `choices[]`); the stem marks each blank as `{{blank:<id>}}` | `{ "blanks": [ { "blank": "b1", "choice_id": "x" } ] }` or `{ "blanks": [ { "blank": "b1", "accepted": [ { "key": "k1", "text": { "en": ["…"], "hi": ["…"] } } ] } ] }` |
| `order_steps` | `steps[]` | `{ "order": ["s2", "s1", "s3"] }` |
| `paragraph` | `passage`, `children[]` (questions of any other type, each with its own ID) | on each child |

- `concepts[].weight` is between 0 and 1. Every concept named must exist in the graph.
- Every solution has a **Feynman-style** plain-language explanation first, then the formal steps. Every type except `paragraph` needs a `solution`.
- `hints` are shown after a first wrong answer when the chosen option has no `common_traps` entry.
- `use` says where the question may appear: `practice` (practice bank and drills), `lesson` (lesson check cards), `placement` (Find my level), `mock` and `daily`. The keys of `mock` and `daily` questions stay on the server (`content.question_keys`) and never ship to devices, so a question with `mock` or `daily` cannot also have `practice`, `lesson` or `placement`, and no lesson card may point to it.
- `source`: `original`, `pyq`, `ncert_exemplar` or `adapted`. A `pyq` question carries `"pyq": { "paper": "<paper id>", "number": 12 }`, and that paper must list it.
- Answer keys must name real option, row, column, step and blank IDs. Every `{{blank:id}}` in each locale of the stem must match `blanks`.
- When a student types a fill-in answer, events record only the matched `key`, never the typed text.
- `difficulty_estimate` is the author's guess (`easy`, `medium`, `hard`). Real difficulty comes later from student data. Never claim a question "appeared in N exams" unless `pyq-ingest` linked it.

## 9. PYQ papers (`pyq/{exam_id}/{paper_id}.json`)

```json
{
  "schema": "pyq-paper@1",
  "id": "jee-main-2025-jan-22-s1",
  "exam": "jee-main",
  "year": 2025,
  "session_label": "22 Jan, Shift 1",
  "held_on": "2025-01-22",
  "paper_code": null,
  "source": { "kind": "official", "url": "https://…", "retrieved": "2026-10-28" },
  "rights_note": "…",
  "items": [ { "number": 1, "question": "q.phy.….0101", "section": "physics-a", "official_answer": "…", "answer_challenged": false } ]
}
```

An item the agency dropped from the paper sets `dropped: true`.

The questions themselves go in `questions/` with `"source": "pyq"` and the `pyq` back-link (§8).

## 10. Mnemonics (`mnemonics/{subject_id}/{chapter_slug}.json`)

```json
{
  "schema": "mnemonics@1",
  "chapter": "chem.periodic-table",
  "items": [
    {
      "id": "m.chem.periodic-table.groups.group-1.1",
      "concept": "chem.periodic-table.groups.group-1",
      "technique": "acrostic",
      "origin": "traditional",
      "taught_in": "…",
      "locale": "hi",
      "text": "…",
      "decodes_to": ["…", "…"],
      "exam_style": null,
      "media": "img.periodic-table.group-1-hook",
      "audio": "audio.periodic-table.group-1-rhyme",
      "notes": "…"
    }
  ]
}
```

- `technique`: `acronym`, `acrostic`, `story`, `rhyme`, `song`, `keyword`, `pao`, `major_system`, `peg`, `palace`, `chunking`, `visual`.
- `origin`: `traditional` (widely known; say where it's commonly taught in `taught_in`), `system` (made by the skill).
- A mnemonic is written in one language (`locale`) and is not translated. Each locale gets its own mnemonic, and `memory_hook` cards and cheat sheets point to one per locale.
- `decodes_to` must exactly match the facts it encodes, in order. `content-qa` checks this.

## 11. Blueprints (`blueprints/{exam_profile_id}/{paper}.v{n}.json`)

See `skills/exam-blueprint/SKILL.md` for the fields. Blueprints are versioned and never edited in place: a pattern change is a new `v{n}` file. `content:check` checks that section counts add up to `question_count`, marks add up to `max_marks`, every question type in a section has a marking rule, and palette colours name real `mockPalette` tokens.

## 12. Media requests (`media/requests/…`)

Content files never contain URLs. They point to a request, and the media skills fulfil it:

```json
{
  "schema": "media-requests@1",
  "requests": [
    {
      "id": "img.kinematics.river-boat",
      "kind": "image",
      "preset": "sunny-scene",
      "subject_family": "physics",
      "brief": "A boat crossing a river, the current shown as gentle arrows, two riverbank trees, no labels",
      "must_show": ["boat heading", "river current direction"],
      "must_not_show": ["text", "numbers"],
      "label_anchors": [ { "id": "current", "x": 0.7, "y": 0.6 } ],
      "alt": { "en": "…", "hi": "…" },
      "used_by": ["phy.kinematics.relative-motion:dd:03"],
      "status": "requested",
      "result": null
    }
  ]
}
```

- `kind`: `image`, `diagram`, `comic`, `pano360`, `animation_rive`, `animation_lottie`, `model3d`, `sim`, `audio_tts`, `audio_song`. It must match the ID prefix.
- Every visual needs `alt` in every locale, or `decorative: true`. Animations and audio carry a `transcript`. Per-locale audio sets `locale`.
- `status`: `requested` → `generated` → `approved` (or `rejected` with `rejected_reason`).
- `result` holds `{ "sha256": "…", "asset_id": "…", "reused": false }` plus optional `mime`, `bytes`, `width`, `height`, `duration_ms`, `licence`, `attribution`, and `sim_id` and `sim_version` for sims. `source_path` (a file under `design/mocks/assets/`) is allowed only in fixtures.
- Only `approved` media can be published.
- Labels are overlaid by the app at `label_anchors`, in the student's language. Images never contain text.

## 13. Extras (`extras/…`)

Every extra has `id` (§2), `scope` (`topic` or `chapter`, with `topic` or `chapter` set to match), `title` and `concepts`, plus:

| `schema` | Fields |
|---|---|
| `cheat_sheet@1` | `key_ideas[]`, `formulas[]` (`name`, `latex`, optional `vault_id`, `concept`), `diagram` (optional), `mnemonics[]` (one ID per locale each), `traps[]` (`mistake`, `correct`) |
| `revision_sheet@1` | `points[]`, `formulas[]` (optional), `diagram` (optional) |
| `storybook@1` | `pages[]` (6–12: `text`, `media`, optional `narration`) |
| `song@1` | `style` (`song`, `rhyme`, `chant`), `versions[]` (one per locale: `locale`, `audio` (an `audio_song` request with a transcript), `lines[]` (`text`, optional `start_ms`/`end_ms`, optional `action`)), optional `minutes`, `cover`, `actions[]` (`id`, `cue`, `icon`) |
| `play@1` | `minutes`, `feedback` (`success`, `try_again`), `rounds[]` (1–6; `kind` `tap`, `match`, `sort`, `drag` or `trace`, each with `prompt` and optional `hint`, `audio`), optional `cover`. See `skills/lesson-author` "Little learners" |

## 14. Seed packs and sims

**Seed pack** (`seed-packs/{variant_id}.json`) says what a store variant ships inside the app:

```json
{
  "schema": "seed-pack-spec@1",
  "variant_id": "jee",
  "exam_profiles": ["jee-main-2027"],
  "locales": ["en", "hi"],
  "chapters": "first",
  "include_placement": true,
  "art": ["img.ui.pet-cat-base"],
  "max_bytes": 8388608
}
```

`chapters` is `"first"` (the first chapter of each subject) or a list of chapter IDs. The publisher fails if the pack is larger than `max_bytes` (8 MB by default).

**Sim manifest** (`sims/{sim_id}/sim.json`, `sim@1`): `id`, `version`, `title`, `origin` (`own`, `phet`, `other_open`), `licence`, `attribution`, `entry`, `bridge_version`, `locales`, `params_schema`, `measurements[]`, `aspect`, `size_bytes` (at most 2 MB), `supports_low_power`, `poster`, `concepts`. See `skills/sim-builder`.

## 15. Coverage inputs

**Syllabus** (`coverage/syllabus/{exam_profile_id}.json`, `syllabus@1`): `exam_profile` and `lines[]`, each with `ref` (a syllabus ref, §2), `text` (localised) and `concepts` (the concepts that cover the line).

**Inventory** (`coverage/inventory/{subject_id}/{chapter_slug}.json`, `inventory@1`): `chapter` and `items[]`, each with `id`, `kind` (`definition`, `law`, `formula`, `constant`, `named_reaction`, `date`, `list`, `diagram`, `solved_example`, `exercise_type`, `fact`), `title`, `source_ref`, `concepts`, and `out_of_syllabus` (the reason) when `concepts` is empty. It lists what the textbook chapter teaches, so nothing in it is skipped by accident.

**Coverage report** (`coverage/{exam_profile_id}.json`, `coverage@1`) is generated by `content:check --write-coverage`. A concept in the exam map is covered when, counting only cards at or below the exam's depth, it has:

- a teaching card in a Deep Dive, a card in a Quick Revision and a `summary` card;
- a question with `use` including `practice`;
- for `formula` concepts, a `formula` card and a `worked_example`;
- for `list` and `date` concepts, a mnemonic in every locale of the profile.

A subject is ready when all its concepts are covered and its syllabus lines and inventory items are all mapped (PRD §14).
